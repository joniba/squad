2. DELIVERY MECHANISM (Teams Incoming Webhook)
   ✅ ALIGNED: Uses Tamir's battle-tested pattern.
   - Same storage: ~/.squad/teams-webhook.url
   - Same transport: Invoke-RestMethod POST to webhook URL

3. MESSAGE FORMATTING (Adaptive Cards + Emoji)
   ✅ ALIGNED: Inherits news-broadcasting pattern.
   - Emoji headers (🔴 urgent, 🟡 action, 🔵 feature) match squad-skills style

4. BATCHING & REMINDERS (Hourly feature digest + active reminders)
   ⚠️ ENHANCEMENT (not in Tamir's squad-skills):
   - Tamir's patterns: immediate dispatch for all events
   - Your design: batch Feature notifications hourly (or queue ≥ 5 items); send reminders at 6h (urgent) and 48h (action)
   - Assessment: Smart innovation for high-volume scenarios. Tamir's immediate dispatch is fine for urgent items (which you keep immediate). Batching prevents notification fatigue for features.
   - Validation needed: Test with squad. Run 1-week pilot; collect feedback on batch timing. Adjust if users prefer immediate dispatch or longer windows.

5. STATE MANAGEMENT (notifications-state.json watermark)
   ✅ SOUND: Tamir uses implicit GitHub issue state; you centralize state.
   - Your approach: explicit .squad/notifications-state.json (gitignored) with per-event retry/error counts
   - Advantage: More scalable, independent of GitHub API rate limits, easier to debug
   - Watch for: State file growth. If >1000 events, implement archival (move >30-day-old events to archive file).

6. INTEGRATION POINTS (Squad Scheduler, GitHub PRs, IcM incidents)
   ✅ ALIGNED: All sources match existing squad-skills workflows.
   - Script failures → teams-monitor already monitors these
   - Blocked issues → teams-monitor filters for these
   - PR reviews → teams-monitor can query these via WorkIQ
   - Your design integrates all of these with structured routing. No conflicts.
