### 🔴 BLOCKING (Must Fix Before Merge)

#### [BUG-1] `validate-bulkactions.ps1` — Poll loop never exits on `Failed` state (Medium)

**File:** `.github/scripts/validate-bulkactions.ps1`  
**Function:** `Run-BulkAction`  
**Category:** Correctness / Reliability

The polling loop in `Run-BulkAction` only breaks on `"Done"`:

```powershell
for ($i = 1; $i -le 15; $i++) {
    Start-Sleep 5
    try {
        $resp = Invoke-RestMethod -Uri "...bulkactions/${baId}..." -Method GET -Headers $stdHeaders
        $lastState = $resp.properties.state
        if ($lastState -eq "Done") { return "OK" }
    } catch {}
}
return "FAIL|state=$lastState after 15 polls"
```

If the server transitions to `"Failed"`, the loop continues 15 iterations × 5 seconds = **75 seconds of unnecessary waiting** per operation. With 12 bulk operations (Edit + Delete × 6 STIX types), a full `Failed`-state run wastes **~15 minutes** and buries the real failure state under a polling-timeout message.

**Fix:** Add an early exit on failure state:

```powershell
if ($lastState -eq "Done") { return "OK" }
if ($lastState -eq "Failed") { return "FAIL|server state=Failed after $i polls" }
```

**Note:** MerlinBot thread 233885906 caught the same issue in `SKILL.md`'s code example. The bug exists in both the documentation **and the actual script**. Both must be fixed.

---

#### [BUG-2] `tiexpert.agent.md` and `validate-stixapi.ps1` — `return` on token failure does not set exit code (Medium)

**Files:**
- `.github/agents/tiexpert.agent.md` — token acquisition inline block
- `.github/scripts/validate-stixapi.ps1` — token acquisition block

**Category:** Correctness / Automation reliability

Both use `return` when token acquisition fails:

```powershell
# tiexpert.agent.md (and validate-stixapi.ps1):
if (-not $token) { Write-Host "FAIL: Could not acquire ARM token..."; return }
```

`return` exits the current scope but does **not** set a non-zero process exit code. When invoked from CI/automation, the parent process sees `$LASTEXITCODE = 0` (success) even when the script failed to authenticate. The four other validation scripts (`validate-fileimport.ps1`, `validate-bulkactions.ps1`, `validate-stixwebapi.ps1`, `validate-ingestionapi.ps1`) all **correctly** use `exit 1`.

**Fix:**

```powershell
if (-not $token) { Write-Host "FAIL: Could not acquire ARM token. Run az login first."; exit 1 }
```

This must be applied to both files. Confirmed by MerlinBot thread 233885899.

#### [SEC-1] `ti-config.ps1` — Hardcoded PPE subscription and workspace IDs (Medium)

**File:** `.github/scripts/ti-config.ps1`  
**Category:** Security hygiene / Sensitive data

The file commits four PPE environment values directly to source:

```powershell
$subscriptionId = "9bf01d25-92e0-4c2f-b947-da7d982da48f"
$workspaceId    = "6c57eafa-e262-4ee3-a4d7-4a2e73533b61"
$tenantId       = "72f988bf-86f1-41af-91ab-2d7cd011db47"
$ingestionUrl   = "https://api.ti-ppe.sentinel.azure.com"
```

Mitigating factors: this is a private internal repo; these are PPE (non-production) values; the tenant ID is the publicly known Microsoft tenant ID. Severity is therefore **Medium**, not Critical.

Concerns:
1. Subscription IDs and workspace GUIDs in source enable reconnaissance even in PPE.
2. Creates a pattern: if someone later adds prod values "because that's where the config file is," it becomes a High/Critical incident.
3. Many security scanners flag any GUID pattern in config files and will flag this in PRs.

**Recommendation:** Move to a `.env`-style file excluded from git, or read from environment variables at runtime. Example:

```powershell
$subscriptionId = $env:TI_PPE_SUBSCRIPTION_ID
$workspaceId    = $env:TI_PPE_WORKSPACE_ID
```

At minimum, add a `# TODO: move to env var` comment and add `ti-config.ps1` to a candidate-for-gitignore list.

#### [BUG-3] `ti-helpers.ps1` — `Poll-LAQuery` silently swallows all exceptions (Medium)

**File:** `.github/scripts/ti-helpers.ps1`  
**Function:** `Poll-LAQuery`  
**Category:** Reliability / Observability

The catch block in the polling loop is empty:

```powershell
for ($attempt = 1; $attempt -le $MaxRetries; $attempt++) {
    try {
        # ... call LA API ...
        return @{ Success = $true; Rows = $rows }
    } catch {
        # (nothing — exception silently swallowed)
    }
    Start-Sleep $RetryDelaySec
}
return @{ Success = $false; Rows = @() }
```

With `$MaxRetries = 15` and `$RetryDelaySec = 30`, a non-transient failure (auth error, wrong workspace ID, network partition) causes **7.5 minutes of silent waiting** before reporting failure. The actual exception is lost, making debugging nearly impossible.

**Fix:** Log the exception, and consider fast-failing on non-transient HTTP status codes:

```powershell
} catch {
    $detail = Get-ErrorDetail $_
    Write-Host "  [Poll-LAQuery] Attempt $attempt failed: $detail"
    if ($detail -match "^(400|401|403|404):") { break }  # non-transient, stop retrying
}
```

#### [MAINT-1] `.gitignore` — `/nul` entry (Low)

**File:** `.gitignore`  
**Category:** Maintenance / Accidental inclusion

The diff adds `/nul` to `.gitignore`. On Windows, `nul` is a reserved device name — not a file that would ever be tracked. This entry appears to be an accidental residue from a Windows shell command (`> /nul` used to suppress output). It is harmless but should be removed.

**File:** `src/StixAPIs/Sightings/Functions/UpsertSighting.cs`  
**Category:** Maintainability

The constructor registers the 2023-10-01-preview version with a TODO to remove it:

this.AddApiVersion(StixApiConstants.ApiVersionPreview_2023_10_01, this.GetActionForApiVersionPreview20240701Async);
